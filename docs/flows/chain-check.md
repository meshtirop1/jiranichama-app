# Checking the chain on the phone

The promise to members is that nobody can quietly change their chama's history, not even
JiraniChama. The phone is where that is checked.

## How it works (`verifyChain` in `jirani_domain`)

For each entry the server sends, the phone:

1. turns the entry's document into canonical JSON, exactly as the server did;
2. computes its SHA-256 fingerprint and compares it with the hash the server sent;
3. checks the entry points at the fingerprint of the entry before it, and that the
   sequence has no gaps;
4. remembers the last record it checked, its **trusted head** (seq and fingerprint), in
   the phone's secure storage.

It then checks the **platform signatures** (`PlatformKey.verifyHash`): ECDSA P-256 over
the 32-byte entry hash, against the public key from `GET /platform-key/`. A chain with
matching fingerprints but a forged or swapped signature is caught. Records not signed yet
(the server signs a few seconds after writing) are counted and shown as waiting.

## Fast, without trusting less

Checking a signature in Dart costs about 150 ms on a phone, so checking 187 records took
about 30 seconds, and it ran on the UI thread: the whole app froze. Now:

- **The records show at once**, as the server sent them, with "Checking N records on this
  phone…" at the top. The notice turns to the result when the check ends.
- **The check runs on a background isolate** (`Isolate.run`), so scrolling and tapping
  keep working while it runs.
- **Signatures are checked once per record per phone.** Every fingerprint and link is
  still recomputed from the start on every load (fast). Signatures are checked only after
  the trusted head, and only if the record at the trusted head still has the same
  fingerprint: then everything up to it is exactly what this phone checked before. If it
  differs (history changed), every signature is checked again and the change is reported.
- The trusted head is saved only after a clean check. Signing out does not remove it (it
  holds no personal data, only a position and a fingerprint).

A failed check shows a red warning on the Records tab. Still to come: reporting a failure
to the server.

## Why the phone and the server cannot disagree

Both use the same canonical JSON and signature rules and are tested against the same
files (including `platform_signatures.json`, made with a public test key):
`packages/jirani_domain/test/vectors/` here, copied from `vectors/` in the API. The tests
include the hard cases: keys sorted by UTF-16 code units, emoji, control characters,
and the refusal of decimals (money is always whole cents).

## Against the public anchor

Every night the server anchors every chama's chain head publicly (a Merkle root posted to
OpenTimestamps and emailed off-site; jiranichama-api docs/flows/anchoring.md). After the
chain check, the Records tab fetches the chama's latest anchor proof and checks it on the
phone:
1. this phone's own copy of the entry at the anchored seq has the anchored hash;
2. its leaf (`anchorLeaf` in `jirani_domain`) walks the Merkle path to that night's root.

It then says "Matches the public anchor of {date}…", or, in red, that it does not, and
whom to tell. `jirani_domain/test/anchor_test.dart` uses a vector generated by the API, so
phone and server agree on every hash.

## Keys, vouching and the public proof (2026-10-20)

- **Which keys count.** The phone fetches `/platform-keys/` and walks the chain from the key it
  trusts. On a release build that key is built in (`--dart-define=PLATFORM_KEY_FP=…`); on a
  dev build the phone pins the first key it sees. Each later key must be endorsed by the one
  before it. A record signed by any other key fails the check, even if the server says the
  key is fine.
- **Vouch for these records.** Under the check, the Records tab says how many members have
  vouched for the chain and up to which record. Every member's signature is checked on this
  phone, against this phone's own copy. If anyone signed a different history, a red warning
  names them. A member whose phone key is set up can add their own signature, after a
  fingerprint, face or PIN.
- **Share the Bitcoin timestamp proof.** Under the anchor notice, this shares the night's
  `.ots` file, which anyone can check with `ots verify`.

See `docs/flows/trust.md` in the API repository.
